About

I'm a cloud infrastructure engineer specializing in the reliability side — Kubernetes platforms, observability, and the automation that keeps enterprise infrastructure from depending on any one person's memory.

Most of my work sits at the intersection of platform engineering and software engineering: I write Go and Python to replace manual operational processes, not just to script around them. A recurring pattern in my work is finding a process that quietly costs an organization hours every week — an ownership gap, a manual notification workflow, an alert nobody trusts — and rebuilding it as something accountable and automated.

I currently lead a 15-engineer platform team at Bosch Global Software Technologies, running Kubernetes infrastructure and CI/CD platforms at enterprise scale across Azure and on-prem OpenShift. I use GitHub Copilot in agent mode daily and ship AI-assisted, not AI-replaced — I still default to first-principles debugging: find the root cause, not the symptom.

I learn on the fly. Give me a desired end state or a problem statement and I'll work out the best execution path myself — I don't need the unfamiliar broken down for me first. What I do need is to actually understand it: for anything new, I dig into why and how it works underneath, rather than copying the first pattern that gets me unblocked, and I'll push back on "that's just how it's done" when it doesn't hold up to that scrutiny.

Selected work

Service-ownership automation

Go · PostgreSQL · Azure Communication Services

Problem

In a large organization, the person who provisions a service eventually leaves — and the service keeps running with no accountable owner. That's unclaimed spend and a compliance gap, and the existing fix was a manual weekly export-and-mail-merge campaign costing 7–8 hours a week.

Approach

Built a Go CLI that treats a PostgreSQL contact database — queried live via PostgREST — as the source of truth instead of a spreadsheet snapshot. It resolves recipients by contact tier and dispatches templated notifications through Azure Communication Services from a single command.

Result

Cut an estimated 390 hours/year of manual preparation and dispatch to roughly 250, and turned an easily-skipped campaign into a repeatable, on-demand mechanism.

CI/CD platform at scale

GitHub Actions (ARC) · Azure AKS · OpenShift

Problem

Hundreds of internal teams needed reliable, self-hosted CI runners across a hybrid cloud and on-prem footprint, without each team managing its own runner fleet.

Approach

Scaled a self-hosted, auto-scaling GitHub Actions runner platform (ARC) across Azure AKS and on-prem OpenShift, with sane defaults and customizable configs for teams with unusual requirements.

Result

The platform now runs 25,000–45,000 CI/CD jobs a day for internal customer teams.

Also evaluated an AI gateway architecture (Bifrost vs. LiteLLM) for a large developer organization's cross-cloud LLM traffic — recommended an approach based on credential blast radius and egress economics. Not implemented, for organizational rather than technical reasons.
